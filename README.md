# Система электронного голосования (E-Voting System) 

Современная платформа для проведения муниципальных и региональных голосований в городах Российской Федерации. Система обеспечивает прозрачность, безопасность и неизменность результатов.

## О проекте
Данная платформа разработана для автоматизации процессов волеизъявления граждан. Система адаптирована под масштабную инфраструктуру и способна обрабатывать голоса из разных часовых поясов и регионов России — от Калининграда до Владивостока.

### Ключевые особенности:
*   **Региональное деление:** Поддержка структуры по субъектам РФ и городам.
*   **Безопасность:** Высокая устойчивость к нагрузкам и защищенные протоколы передачи данных.
*   **Прозрачность:** Использование современных алгоритмов для проверки подлинности голоса.

## Технологический стек

### Backend
*   **Language:** [Go (Golang)](https://golang.org) — высокая производительность и надежная работа с параллельными процессами.
*   **Linter:** `golangci-lint` — для поддержания качества и чистоты кода.
*   **Database:** PostgreSQL (рекомендуется) для хранения данных о голосованиях.

### Frontend
*   **Library:** [React](https://reactjs.org) — интерактивный и быстрый интерфейс для избирателей.
*   **State Management:** Redux Toolkit / Context API.

## Структура проекта

### 📋 Описание директорий

| Директория | Описание |
|------------|----------|
| **`cmd/`** | Точки входа в приложение. Содержит `main.go` файлы для запуска веб-сервера и выполнения миграций БД |
| **`config/`** | Внешние конфигурационные файлы (TOML, YAML, JSON) |
| **`Docker/`** | Dockerfile'ы и docker-compose конфигурации для контейнеризации |
| **`internal/`** | Приватный код приложения, который не должен импортироваться другими проектами |
| **`internal/app/ds/`** | Структуры данных и доменные модели (City, Event, Person, Application) |
| **`internal/app/handler/`** | HTTP handlers (контроллеры) для обработки входящих запросов |
| **`internal/app/repository/`** | Слой работы с базой данных (CRUD операции) |
| **`internal/app/config/`** | Логика чтения и парсинга конфигурации приложения |
| **`internal/app/dsn/`** | Конфигурация подключения к базе данных |
| **`internal/app/pkg/`** | Вспомогательные функции и утилиты приложения |
| **`resources/`** | Статические файлы: HTML шаблоны, CSS, JavaScript, изображения |

###  Архитектурные принципы

Проект следует **стандартной структуре Go проектов** с разделением по слоям:

1. **Domain Layer** (`ds/`) - бизнес-сущности и модели данных
2. **Handler Layer** (`handler/`) - обработка HTTP запросов, валидация входных данных
3. **Repository Layer** (`repository/`) - работа с базой данных, абстракция хранения данных

Такое разделение обеспечивает:
-  **Чистую архитектуру** и разделение ответственности
-  **Легкость тестирования** каждого слоя отдельно
-  **Возможность замены** базы данных без изменения бизнес-логики
-  **Поддержку и масштабируемость** кода

## Соглашения по именованию

### Backend (Go)
| Элемент | Стиль        | Пример |
|---------|--------------|--------|
| Файлы | `snake_case` | `user_handler.go`, `event_repository.go` |
| Пакеты | `lowercase`  | `package handler` |
| Экспортируемые сущности | `PascalCase` | `type Handler`, `func NewHandler()` |
| Внутренние сущности | `PascalCase` | `func (h *Handler) parseInput()` |

### Frontend (React + TypeScript)
| Элемент | Стиль | Пример |
|---------|-------|--------|
| Компоненты | `PascalCase` | `CreateEventForm.tsx` |
| Хуки/утилиты | `camelCase` | `useAuth.ts`, `apiClient.ts` |
| Переменные/функции | `camelCase` | `const eventCode`, `function fetchVotes()` |
| Типы/интерфейсы | `PascalCase` | `interface VotePayload` |

> В текущей версии проекта файлы бэкенда используют `PascalCase` (например, `Handler.go`).
> Это отклонение от стандарта будет исправлено в следующем релизе.

# Установка и запускв

### Требования
- Docker и Docker Compose
- Go 1.21+
- Make (опционально, для удобства)

---

### Шаг 1: Запуск Docker

```bash
# Запустить только контейнер с БД
docker-compose up -d 

# Проверить, что БД поднялась
docker-compose ps

# Просмотреть логи (если что-то не так)
docker-compose logs -f 
```
### Шаг 2: Запуск серверной части
```bash
# Переход в директории запускающей сервер
cd WebApp

# Запуск проекта main.go
go run main.go
```

## 🔧 Качество кода и линтинг

Проект использует инструменты автоматического контроля качества кода для поддержания единого стиля и предотвращения ошибок.

### 🎯 Pre-commit Hooks

Для автоматической проверки кода перед коммитом используется [pre-commit](https://pre-commit.com/).

#### Установка

```bash
# Установите pre-commit (требует Python)
pip install pre-commit

# Или через Homebrew (macOS)
brew install pre-commit

# Инициализируйте хуки в репозитории
pre-commit install

# Проверка всех файлов вручную
pre-commit run --all-files
```
```bash
# Запустить линтер во всём проекте
golangci-lint run

# Запустить с авто-исправлением (если поддерживается)
golangci-lint run --fix

# Проверить конкретный файл
golangci-lint run ./internal/app/handler/Event.go

# Вывести подробный отчёт
golangci-lint run --out-format=colored-line-number
```
